# 未来扩展

这份文档回答两个问题：如果继续投入，往哪里扩展、按什么优先级做；以及现有架构为这些扩展预留了哪些扩展点，改动会落在哪里。

## 1. 现有扩展点

| 扩展点 | 位置 | 现在能做什么 | 将来可以做什么 |
| --- | --- | --- | --- |
| `Agent` 接口 | `src/lib/agents/core/types.ts` | 内置四个角色和自定义智能体都实现它，编排器只依赖这个接口 | 新增任意角色（QA、数据分析、SEO 等），不改主流程 |
| 工厂函数 | `src/lib/agents/core/factories.ts` | `defineJsonAgent` 几行配置就是一个结构化输出的角色；`defineCustomAgent` 接收纯数据配置 | 从数据库、模板市场或可视化编辑器生成智能体 |
| 共享上下文 `AgentContext` | 同上 | `artifacts`（结构化产物）和 `notes`（给后续成员的建议）在成员间传递 | 加入截图、运行日志、用户上传的设计稿等新的上下文类型 |
| 运行时能力 `AgentIO` | 同上 | `json()`、`stream()`、`status()`、`emit()` | 加入 `tool()`（工具调用）、`browse()`（无头浏览器）、`search()` 等能力，所有智能体自动获得 |
| 流水线控制 | `runPipeline` | 顺序执行，`when()` 决定出场，`halt` 可提前结束 | 条件分支、循环（QA 不通过就回到工程师）、并行（多位顾问同时评审） |
| LLM 适配层 | `src/lib/agents/llm.ts` | 任意 OpenAI 兼容服务，环境变量切换 | 按智能体选模型（便宜模型做路由，强模型写代码），多供应商降级 |
| SSE 事件协议 | `src/lib/agents/events.ts` | 前端按事件类型渲染 | 新增事件类型（如 `qa_report`、`screenshot`），前端加一个渲染分支即可 |
| 预览运行时 | `src/lib/runtime.ts` | Storage 替身、错误上报 | 元素选取、网络请求代理、性能采集 |
| 数据库迁移 | `supabase/migrations/` | 增量脚本按序号执行 | 新功能各自带迁移，旧库可平滑升级 |

## 2. 扩展方向与优先级

优先级的判断依据：对"生成结果是否可用"的影响最大的先做；能复用现有扩展点、改动小的先做；需要新基础设施的放后面。

### P0：让生成结果更可靠

| 方向 | 做法 | 落点 |
| --- | --- | --- |
| **QA 智能体与自动验收** | 工程师之后加一位 QA：在无头浏览器中打开预览，截图并收集运行错误，不通过就把报告交回工程师修复，最多循环 N 次 | 新增 `AgentIO.browse()`；流水线支持"回到某个成员"的循环；现在的"让 Alex 修复"按钮就是这个流程的手动版 |
| **生成任务持久化** | 新增 `generations` 表记录状态和事件流；生成与浏览器连接解耦（Vercel `waitUntil` 或队列），刷新页面后可以恢复进度；同一项目同时只允许一个进行中的任务 | 编排器把 `emit` 同时写入数据库；前端重连时先回放历史事件 |
| **按角色选模型** | Mike 的意图判断用小模型，工程师用强模型；某个供应商失败时自动切换到备用模型 | `LLM` 接口加 `model` 参数，`Agent` 声明偏好的模型档位 |

### P1：让交互更自然

| 方向 | 做法 | 落点 |
| --- | --- | --- |
| **可视化选取编辑** | 预览中开启选取模式，点击元素后把选择器和 HTML 片段作为上下文附在输入框上，例如"把这个按钮改成圆形" | 预览运行时增加选取脚本，通过 postMessage 回传；工程师提示词带上片段，补丁定位更准 |
| **需求澄清** | 需求模糊时，Emma 先给出 2 到 3 个带选项的问题卡片，用户点选后再开工 | Emma 的 schema 增加 `questions` 字段，返回问题时 `halt`；前端渲染选项卡片 |
| **PRD 随迭代演进** | 新功能类的修改先由 Emma 输出 PRD 补丁，编辑器新增"需求文档"标签页查看历史 | Mike 的意图细分为"新功能 / 修 bug / 改样式"，按意图组装不同流水线 |
| **图片输入** | 上传截图或设计稿，由多模态模型还原成页面 | `AgentContext` 加入图片；换用支持视觉的模型 |

### P2：让平台更开放

| 方向 | 做法 | 落点 |
| --- | --- | --- |
| **智能体市场** | 自定义智能体可以公开分享，其他用户一键添加到自己的团队，按使用次数排序 | `custom_agents` 加 `is_public`，新增"复制到我的团队"；配置本身已经是可序列化的纯数据 |
| **智能体工具调用** | 自定义智能体可以声明工具（搜索、读取 URL、调用用户提供的 API） | `AgentIO.tool()`，配合模型的 function calling；工具白名单 + 用量限制 |
| **多文件工程** | 引入 WebContainer 或服务端构建，支持 React 等框架和 npm 依赖 | 版本从单个 `html` 变为文件树（`versions` 改存 JSON 或对象存储）；预览改为构建产物 |
| **生成应用的云端数据** | 为生成的应用提供按项目隔离的 KV 或表存储 API，发布出去的应用可以多人共享数据 | 预览运行时的 Storage 替身改为调用后端；按项目做配额和访问控制 |
| **自定义域名与一键部署** | 发布到自定义域名，或导出到 Vercel、Netlify | 发布页增加部署目标；版本导出为静态站点 |

### P3：协作与商业化

- **多人协作**：项目成员、角色权限、评论与 @，RLS 从"本人"扩展为"项目成员"。
- **版本分支**：从任意版本分叉出新的方向，对比后合并。
- **用量与计费**：记录每次生成的 token 消耗和耗时（`generations.usage`），按套餐限额，替代现在按次数的限流。

## 3. 工程层面的演进

| 方向 | 现状 | 演进 |
| --- | --- | --- |
| 可观测性 | 结构化 JSON 日志，带请求 id、耗时、错误码 | 接入链路追踪（每个智能体一个 span）、token 成本看板、错误率告警 |
| 测试 | 单元测试覆盖解析、补丁、团队组装、流水线、错误映射、SSE；端到端覆盖三条主流程 | 提示词回归评测：固定一组需求，定期跑真实模型，对生成结果做可运行性和功能点检查 |
| 安全 | iframe 沙箱隔离生成代码，RLS 隔离数据，API Key 只在服务端，按账号限流 | 发布页放到独立域名彻底隔离 Cookie；提示词注入防护；生成内容审核 |
| 性能 | 单次生成串行调用 3 到 4 次模型 | 规划阶段并行化（架构师与自定义顾问并行），PRD 生成缓存，流式渲染更早可见 |
